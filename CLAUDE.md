# Siba Hunter — правила проекта

Браузерный платформер на Phaser 3. Сиба-ину собирает косточки, прыгает на
котов, доходит до флага.

## Главное

**Сборки нет.** Обычные `<script>`-теги, Phaser с CDN, статика на GitHub
Pages. Не добавляй npm-сборку, бандлеры, TypeScript или модули ESM —
игра должна открываться двойным кликом по `index.html` без сервера.

**Контент отделён от кода.** Уровни, спрайты и история обновлений — это
данные в текстовом виде. Большинство задач решаются правкой данных, а не
логики.

## Карта файлов

Пути строгие. Файл, положенный не в ту папку, не подхватится.

```
index.html          главная: шапка, канвас, подвал
changelog.html      страница обновлений
changelog.js        версия, история, текст поста в Telegram
style.css           стили обеих страниц
og.png              карточка для ссылок (картинка, текстом не правится)

src/
  main.js           конфиг Phaser, масштабирование под окно
  site.js           версия в шапке, рендер списка обновлений
  touch.js          экранные кнопки для телефона
  sprites.js        пиксель-арт: собака, кот, косточки
  levels.js         карты уровней
  save.js           прогресс и таблица рекордов в localStorage
  run.js            состояние забега: жизни, размер, таймер
  scenes/
    GameScene.js    физика, управление, враги, финиш
```

Порядок подключения в `index.html` важен: `sprites.js` и `levels.js`
должны идти **до** `GameScene.js`, а `main.js` — последним.

## Уровни

Карта рисуется символами в `src/levels.js`. Один символ = клетка 32x32.

| символ | что это |
|---|---|
| `#` | земля, сплошной блок |
| `=` | платформа, занимает верхнюю половину клетки |
| `o` | косточка |
| `G` | золотая косточка, делает собаку большой |
| `P` | старт игрока, ровно один |
| `F` | флаг-финиш, ровно один |
| `E` | кот-противник |
| пробел | пустота |

### Обязательные инварианты

Нарушение любого ломает уровень молча — проверяй расчётом, а не на глаз.

1. **Все строки уровня одной длины.** Высота ровно 16 строк.
2. **Ровно один `P` и один `F`.**
3. **Флаг стоит на земле.** Спрайт флага 64px высотой, его центр ставится
   в верх клетки. Значит низ флага `(строка+1)*32` обязан совпасть с
   верхом земли под ним. Ошибка на строку — флаг висит в воздухе и
   стоящая собака до него не достаёт.
4. **Каждая яма перелетаема.** При скорости 210, прыжке 520 и гравитации
   950 время полёта над ямой в `g` клеток равно `(g+1)*32/210`, высота
   подъёма к этому моменту `520t - 475t²`. Она должна быть не меньше
   подъёма до следующей площадки.
5. **Под низким потолком нужно считать обе комплекции.** Малая собака
   30px высотой, большая 60px. Свобода над головой = `(строка_земли*32 -
   высота_собаки) - (строка_потолка+1)*32`. Для большой собаки её должно
   хватать на подъём из пункта 4.
6. **У каждого кота есть опора и место.** Под `E` должна быть площадка
   шириной хотя бы 5 клеток, иначе кот дёргается на месте.
7. **На свод нельзя запрыгнуть сверху.** Полный прыжок поднимает собаку
   на 142px — верх любого свода должен быть выше досягаемости.

Числа физики живут в `TUNING` в начале `src/scenes/GameScene.js`.
**Геометрия уровней от них зависит.** Меняешь прыжок или гравитацию —
пересчитывай все ямы на всех уровнях.

## Спрайты

`src/sprites.js`: сетки символов плюс палитра `PIXEL_COLORS`. Собака и кот
собираются из неизменного тела и вариантов лап — так кадры анимации не
дублируют весь спрайт. Размер сетки произвольный, подставляется сам.

Картинок в проекте нет и добавлять не нужно: всё рисуется кодом через
`drawPixelArt`.

## Версии и changelog

`changelog.js` — **единственное место, где живёт номер версии.** Из него
берутся бейдж в шапке, страница обновлений и текст поста в Telegram.

- Новая запись добавляется **сверху**, первый элемент массива всегда текущая версия.
- Типы изменений: `level`, `feat`, `fix`, `chore`.
- Заметное игроку → растёт средняя цифра (`0.13.0` → `0.14.0`).
  Мелкая правка → младшая (`0.13.0` → `0.13.1`).
- Текст записей пишется для игрока, а не для разработчика: «коты теперь
  разворачиваются у края», а не «добавлен метод groundAhead».

**Пуш в `main` с изменённым `changelog.js` автоматически публикует пост в
Telegram-канал.** Не поднимай версию, если менял только внутреннее
устройство без видимого эффекта.

## Чего не делать

- Не добавлять сборку, зависимости из npm, файлы картинок и шрифтов.
- Не использовать `localStorage` где-то кроме `save.js`.
- Не дублировать номер версии вне `changelog.js`.
- Не менять адрес сайта в мета-тегах и `telegram.yml`.
- Не трогать `check.bat` и `deploy.bat` — это скрипты для машины
  владельца, под Windows, в CI они не запускаются.

## Перед тем как открыть PR

1. `node --check` на каждый изменённый `.js`.
2. Если менялись уровни — посчитать инварианты 1-7 выше и **приложить
   расчёт в описание PR**: ширины строк, зазоры, требуемая и доступная
   высота прыжка.
3. Если менялась физика в `TUNING` — пересчитать все уровни.
4. Проверить, что новые файлы лежат по правильным путям и подключены в
   `index.html` в правильном порядке.
5. Добавить запись в `changelog.js`, если изменение заметно игроку.

В описании PR коротко: что сделано, какие файлы затронуты, что проверено.
